# 교재 엮기 — 낱장을 한 권으로

> **레이어: 스킬** — 어떤 순서로 하는가.
> 판단 기준(무엇을 통일하고 무엇을 남기는가)은 `~/.claude/agents/learning-editor.md`. 용어·문체 규약은 `~/.claude/instructions/교재-공통규약.md`.

---

## 0단계 — 내 차례가 맞는지 확인한다

편집자로서 쓰기 파일 목록을 배정받았을 때만 수행한다. 단계를 바꾸거나 검수자를 직접 부르지 않는다.

```bash
python3 ~/.claude/orchestration/book.py check <출력경로> --stage review
```

두 가지를 본다.

- **S1이 남아 있는가** — 남아 있으면 집필자 수정이 먼저다. S2만 남았다면 편집을 진행하며 미처리 ID·이유를 인계 문서에 남긴다
- **판정이 아직 유효한가** — `check`가 잡는다. 검수한 판본과 현재 원고의 해시가 다르면 그 `S1: 0`은 낡은 숫자다. 재집필된 챕터에 옛 리포트가 남아 있는 경우가 실제로 가장 흔하다

어느 쪽이든 걸리면 **작업하지 않고 지휘자에게 알린다.**

## 1단계 — 전 챕터를 읽는 순서대로 통독한다

훑지 않고 읽는다. 이 단계의 목적은 고칠 곳을 찾는 게 아니라 **이어 읽었을 때 어디서 걸리는지** 느끼는 것이다. 읽으면서 메모만 하고 아직 고치지 않는다.

메모할 것: 표기가 갈린 용어 · 같은 설명이 두 번 나온 곳 · 뚝 끊기는 이음매 · 갑자기 어려워지는 지점.

## 2단계 — 용어 표기를 통일한다

설계서 용어집이 기준이다. 실제 사용을 먼저 수집한다.

```bash
grep -rno '커넥션 풀\|커넥션풀\|connection pool\|커넥션 pool' chapters/ | sort | uniq -c
```

- 용어집에 있는 표기로 통일한다
- 용어집에 없는 용어는 후보 표기를 보고한다. 용어집 수정은 설계자의 쓰기 범위이므로 직접 추가하지 않는다
- 판단이 갈리면 고치지 말고 「지휘자 보고」에 적는다
- 영문 병기는 **책 전체에서 최초 1회**만 남긴다. 챕터마다 반복되면 뒤의 것을 지운다

## 3단계 — 중복 설명을 정리한다

같은 개념이 두 곳 이상에서 설명되면 **계약의 소유 챕터를 확인한다.** 먼저 나온 챕터가 아니라 소유 챕터를 남긴다.

```bash
grep -rn '커넥션 풀' 00-설계/챕터계약/ | grep -i '다루는 것' -A3
```

남기지 않는 쪽은 한 줄 + 참조 링크로 줄인다.

```markdown
커넥션 풀의 동작 원리는 [3.2](03-커넥션-풀-크기.md#32-대기는-어디서-발생하는가)에서 다뤘다.
```

**지우기 전에 반드시 계약을 확인한다.** 뒤 챕터의 본론을 "앞에 나왔으니까"로 지우면 그 챕터가 무너진다. 애매하면 지우지 말고 보고한다.

## 4단계 — 이음매를 잇는다

챕터 N의 끝과 N+1의 첫 문단을 나란히 놓고 본다.

- N의 「다음 장으로 넘기는 문제」를 N+1의 첫 문단이 받는가
- 안 받으면 **받는 한 문장을 쓴다.** 내가 새로 쓸 수 있는 문장은 이것과 `index.md`뿐이다
- 앞에서 "뒤에서 다루겠다"고 한 약속을 전부 찾아 실제 챕터로 링크한다

```bash
grep -rn '뒤에서\|나중에 다룬\|후술\|다음 장에서' chapters/
```

약속을 지키는 챕터가 없으면 **고치지 말고 「지휘자 보고」에 적는다.** 그건 설계 누락이다.

## 5단계 — 상호 참조 링크를 건다

- 상대 경로 + 앵커: `[3.2 대기는 어디서 발생하는가](03-커넥션-풀-크기.md#32-대기는-어디서-발생하는가)`
- 앵커 규칙: 제목을 소문자로, 공백은 `-`, 마침표·괄호 등 문장부호는 제거. 한글은 그대로
- 링크를 건 뒤 **전부 확인한다**

```bash
grep -rno '](\([0-9]\{2\}-[^)]*\))' chapters/ index.md | sed 's/.*](//;s/)//' | sort -u
```

가리키는 파일이 없거나 앵커가 없는 링크는 남기지 않는다.

## 6단계 — S3를 처리하고 형광펜을 정리한다

검수 리포트의 S3 항목을 처리한다. 형광펜은 **개수 초과만** 정리한다 — 소단원당 합계 3개를 넘으면 가장 약한 것부터 뺀다. **색을 바꾸지 않는다.** 색은 집필자의 판단이다.

노랑만 이어 읽어 책 전체 요약이 되는지 마지막으로 확인한다.

## 7단계 — index.md를 쓴다

책의 얼굴이자 학습 지도다. 새 설명을 쓰는 곳이 아니라 **길을 안내하는 곳**이다.

```markdown
# <책 이름>

<한 줄 소개> · 독자: <독자> · 총 <N>장 · 예상 <합계>분

## 읽는 순서
- **기본 코스** — 01 → 02 → 03 → … (전부, <합계>분)
- **급행 코스** — <핵심 챕터만>, <시간>분. <어떤 독자에게 맞는지 한 줄>

## 챕터
| # | 제목 | 이 장에서 답하는 질문 | 시간 |
|---|---|---|---|
| [01](chapters/01-….md) | … | … | 30분 |

## 학습 지도
<설계서의 의존성 그래프(Mermaid)를 그대로 옮긴다>

## 다 읽으면 답할 수 있는 질문
<전 챕터 계약의 질문을 모아 챕터 번호와 함께 나열한다>

## 용어 색인
| 용어 | 표기 | 처음 나오는 곳 |

## 남은 것
<집필자들의 이월제안 · 미처리 S2 · 지휘자 보고 항목>
```

「다 읽으면 답할 수 있는 질문」은 각 챕터의 질문을 **그대로** 옮긴다. 새로 쓰지 않는다.

## 8단계 — 난이도 곡선을 점검한다

읽는 순서대로 챕터별 새 개념 수와 분량을 훑는다. 갑자기 어려워지는 지점 — 새 개념이 앞 챕터의 2배 이상 쏟아지는 곳 — 을 찾는다.

**고치지 않는다. 위치와 이유를 「지휘자 보고」에 적는다.** 여기서 챕터를 손보면 방금 맞춘 용어와 브리지가 다시 어긋난다.

## 9단계 — 자가 점검과 보고

- [ ] 용어집 표기가 전 챕터에 적용됐다. 영문 병기는 책 전체 1회
- [ ] 중복 설명이 소유 챕터에만 남았다 (지운 것은 전부 계약 확인 후)
- [ ] 모든 챕터 이음매가 맞물린다
- [ ] "뒤에서 다루겠다" 약속이 전부 링크로 연결되거나 보고됐다
- [ ] 링크가 전부 유효하다
- [ ] 형광펜 개수가 소단원당 3개 이내
- [ ] `index.md`의 챕터 표·질문 모음·시간 합계가 실제와 맞는다
- [ ] **새 내용을 추가하지 않았다.** 내가 쓴 문장은 이음매와 index.md뿐이다
- [ ] **사실 판단을 하지 않았다**

마지막으로 한 번 더 돌린다. 이 단계에서 링크와 앵커를 대량으로 건드렸기 때문이다.

```bash
python3 ~/.claude/orchestration/book.py check <출력경로> --stage draft
```

편집한 챕터는 해시가 바뀌어 이전 검수 판정이 무효다. 변경 파일과 영향 범위를 지휘자에게 넘기고 독립 재검수를 기다린다. 편집자가 검수 리포트의 해시를 갱신해 통과시키지 않는다. 재검수 후 `index.md`의 남은 항목 갱신만 재배정받을 수 있다.

단일 파일 합본은 지휘자가 final 게이트 통과 후 `book.py build`로 생성한다. 이 스킬이 단계 완료나 인계를 결정하지 않는다.

**합본은 재생성물이다.** 합본을 고치지 않는다 — 고칠 것이 있으면 챕터를 고치고 다시 만든다. 두 벌을 손으로 관리하면 반드시 갈라진다.

지휘자에게 돌려줄 보고 — 변경 파일 · 통일한 용어 목록 · 축약한 중복 위치 · 새로 쓴 이음매 수 · 남은 S2/S3 · **「지휘자 보고」 항목**(사실 의심 · 지켜지지 않은 약속 · 난이도 급변 · 판단 보류한 용어).
