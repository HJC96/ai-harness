# 장의 근거 조사

입력은 사용자 요청과 승인된 장별 명세다. 출력은 배정된 `research/<chapter-id>.md`와 인수인계 문서다. [작업 계약](../../instructions/book-contract.md)을 따른다.

## 절차

1. 장에서 가르칠 핵심 주장, 흔한 오해, 버전·시점에 따라 달라지는 내용을 뽑는다. 사용자가 지정한 자료·조사 제한을 확인한다.
2. 접근 가능한 사용자 자료부터 읽고, 필요하고 허용된 경우 공식 문서·표준·원 논문·원 데이터를 조사한다. 기술 API나 버전 동작은 공식 문서를 우선한다. 검색 요약만 보고 출처를 확인했다고 쓰지 않는다.
3. 주장마다 아래 내용을 기록한다.
   - 주장 ID와 설명하려는 내용.
   - 근거의 제목, 실제 확인한 URL 또는 로컬 경로·절, 확인 날짜, 적용 버전.
   - 근거가 뒷받침하는 범위와 한계, 예외·반례.
   - 상태: `verified`, `background`, `unverified`.
4. `verified`는 실제 읽은 근거가 있는 경우에만 사용한다. 안정된 일반 지식으로 설명한 항목은 `background`로 구분하고 출처를 꾸미지 않는다. 불확실한 항목은 `unverified`로 남긴다.
5. 핵심 개념을 보여줄 예제의 조건·예상 작동 원리·검증 방법을 기록한다. 코드를 실행했다면 실제 명령·환경·결과를 적고, 실행하지 않았다면 미실행으로 적는다.
6. 자료 간 충돌, 접근 실패, 최신 확인이 필요한 공백을 따로 정리한다. 핵심 주장에 해결되지 않은 공백이 있으면 결과 상태를 `blocked` 또는 `needs_revision`으로 반환한다.

## 결과 기준

집필자가 어떤 설명이 근거에 기반하고 어떤 내용이 교육용 단순화인지 구분할 수 있어야 한다. 웹 사용이 금지되었으면 제공 자료와 명시한 한계 안에서 작업한다. 최신 정보가 필수인데 확인할 수 없다면 예전 지식으로 검증 완료를 주장하지 않는다.

조사 자료는 주장 중심으로 작성한다. 책 본문을 대신 집필하거나 팀의 다음 작업을 실행하지 않는다.
