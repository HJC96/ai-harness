# 학습서 장 집필

입력은 사용자 요청, 장별 명세, 해당 조사 자료, 설계에 적힌 앞 장의 이어받을 문장이다. 선행 장 전문은 그것 없이는 쓸 수 없을 때만 받는다. 선행 장을 통째로 읽으면 그 내용을 요약하며 시작하게 되고 같은 설명이 두 장에 남는다. 출력은 배정된 `chapters/<chapter-id>.md`와 인수인계 문서다. [작업 계약](../../instructions/book-contract.md)을 따른다.

## 절차

1. 해당 장의 목표와 원문 목차 항목을 확인한다. 독자가 지금까지 아는 내용, 여기서 처음 배우는 내용, 다음 장으로 이어지는 내용을 구분한다. 설계의 제외 주제와 소유 장 ID를 함께 확인한다. 제외 주제는 한 문장 언급과 소유 장 참조까지만 쓴다. 설계에 없는데 필요해 보이는 주제는 본문에 넣지 말고 인수인계에 남긴다. 눈에 구멍으로 보이는 것이 대개 다른 장의 본론이다.
2. 설계에 적힌 이어받을 문장을 받아서 시작한다. 왜 이 내용을 배우는지 구체적인 질문이나 상황으로 연결한다. 용어를 처음 사용할 때 설명하고, 원인·작동 과정·결과의 관계를 문단으로 풀어 쓴다.
3. 개념의 정의 뒤에는 독자가 추론을 따라갈 수 있는 예제를 둔다. 설계가 관통 사례와 이 장이 쓸 장면을 지정했으면 그것을 쓰고, 한 장면으로 부족하면 같은 사례를 정상·실패·극단·복구로 변주한다. 비슷한 원리의 새 사례를 만들지 않는다. 장마다 새 사례가 등장하면 독자는 장마다 상황 설정을 다시 이해해야 한다. 가정, 진행 과정, 결과 해석, 적용되지 않는 상황을 설명한다.
4. 헷갈리기 쉬운 개념을 구별한다. 한계를 숨기는 비유, 근거 없는 일반화, 설명 없이 등장하는 전문 용어를 고친다. 조사 자료의 불확실한 핵심 주장은 확정 사실로 쓰지 않고 문제로 반환한다.
5. 학습 목표를 확인할 연습과 해설을 작성한다. 단순 암기 확인뿐 아니라 적용·이유 설명을 포함하고, 해설에는 답에 이르는 과정과 흔한 오답의 원인을 설명한다. 문제 수와 유형은 장의 목표에 맞춘다.
6. 다음 장과의 연결은 설계에 적힌 넘길 문제를 쓴다. 설계에 없으면 새로 지어내지 말고 인수인계에 남긴다. 연결을 적고 장 안의 표기·예제·연습 답을 점검한다. 실제 읽은 근거를 필요한 주장 가까이에 연결하고 장 끝에 참고 자료를 정리한다.
7. 수정 작업이면 지적 ID별로 어느 부분을 어떻게 고쳤는지 인수인계에 남긴다. 해결하지 못한 지적을 해결한 것으로 표시하지 않는다.

## 본문 형식

- 장 제목은 H1 하나를 사용하고 본문은 H2 이하로 구성한다.
- 목표와 선수 지식, 연결된 본문, 설명이 있는 예제, 연습과 해설, 마무리 연결을 포함하되 소제목·순서는 주제에 맞게 정한다.
- 분량은 요청과 학습 목표에 맞춘다. 문단을 반복해서 늘리거나 제목·글머리표만 나열해 본문을 대체하지 않는다.
- 코드 블록에는 언어를 표시한다. 실제 실행 결과와 설명을 위한 예상 결과를 구분한다.
- 원고 안의 상대 링크·이미지는 그 원고 파일 위치를 기준으로 유효해야 한다. 다른 장을 참조하면 장 ID와 관련 절을 함께 적는다.
- 작업 ID, 단계 이름, 역할 간 지시 등 집필 운영 정보는 본문에 넣지 않고 인수인계 파일에 기록한다.

이 스킬은 배정된 장의 집필만 수행한다. 조사 명세·다른 장을 임의로 수정하거나 독립 검토를 대신하지 않는다.
