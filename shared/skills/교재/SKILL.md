# 교재 — 목차를 한 권의 학습 교재로 `/교재`

> **레이어: 스킬(진입점)** — 요청을 접수해 파이프라인에 넘기는 절차.
>
> **이 스킬이 담지 않는 것: 팀 구성 · Phase · 배치 · 게이트.** 그건 전부 `~/.claude/orchestration/교재-파이프라인.md`가 가진다. 여기에 워크플로를 추가하고 싶어지면 그 파일을 고친다. 이 스킬이 팀을 지휘하기 시작하면 지휘 규칙이 두 군데로 갈라지고, 둘은 반드시 어긋난다.

## 이 스킬이 하는 일

1. 입력 네 가지를 확정한다
2. 요청 모드를 입력값으로 기록한다
3. 입력과 모드를 메인 세션의 오케스트레이터에 넘긴다. 단계 선택과 팀 배치는 수행하지 않는다

기존 원문을 요약하기만 하는 작업은 이 하네스의 대상이 아니다. 목차를 기준으로 새 교재를 쓰면서 참고할 원자료가 있는 경우에는 그 경로도 접수한다. 다른 개인 스킬 설치를 전제로 하지 않는다.

---

## 1단계 — 입력을 접수한다

네 가지를 확정한다. **이미 알 수 있는 것은 묻지 않는다.** 되묻기는 확정되지 않은 것만.

### 목차

형태별로 처리가 다르다.

| 형태 | 처리 |
|---|---|
| 대화에 붙여넣음 | 원문을 그대로 접수한다. 저장은 파이프라인의 접수 규칙을 따른다 |
| 파일 경로 | 읽는다 |
| 이미지·PDF | 전부 확인한다. 판독되지 않는 항목은 표시해 전달하고 그 부분만 확인한다. 읽지 못한 부분을 추정해 채우지 않는다 |
| 책 제목만 있음 | **목차를 지어내지 않는다.** 목차를 달라고 요청한다 |

목차를 받으면 **계층만 정규화**한다 — 장/절 깊이, 번호. 표현은 원문 그대로 둔다. 항목을 합치거나 순서를 바꾸는 판단은 `curriculum-architect`의 일이다.

### 독자

지정이 없으면 `~/.claude/instructions/교재-공통규약.md`의 기본 독자(실무 3~5년차 Java·Spring 백엔드, 면접 준비 병행)로 두고 **가정을 밝힌다.** 되묻지 않는다.

### 출력 경로

없으면 `./<책이름>/`을 제안한다. 책 이름은 목차 최상위 제목에서 만든다. 이미 있는 디렉터리면 「이어서」 모드인지 확인한다.

### 깊이

`표준`(챕터당 25~40분) / `압축`(15분) / `정밀`(45~60분). 지정이 없으면 `표준`.

---

## 2단계 — 모드를 판별한다

인자는 `/교재` 뒤 텍스트(`$ARGUMENTS`)로 들어온다.

| 모드 | 호출 | 접수할 의도 |
|---|---|---|
| 신규 | `/교재 <목차 경로나 내용>` | 새 교재 작성 |
| 이어서 | `/교재 이어서 <출력경로>` | 기존 작업 재개 |
| 검수 | `/교재 검수 <출력경로>` | 기존 원고 검수 |
| 재집필 | `/교재 재집필 <출력경로> <챕터번호>` | 지정 챕터 수정 |
| 상태 | `/교재 상태 <출력경로>` | 진행 상황 조회 |
| 설계만 | `/교재 설계 <목차>` | 설계 산출물까지만 작성 |

상태 파일이 없다고 신규로 단정하지 않는다. 기존 파일 유무와 요청 모드를 함께 전달한다. 기존 챕터를 덮어쓰지 않는다.

---

## 3단계 — 파이프라인에 넘긴다

`~/.claude/orchestration/교재-파이프라인.md`를 읽는다. 없으면 이 저장소의 `shared/orchestration/교재-파이프라인.md`를 읽는다.

**접수한 입력 네 가지와 요청 모드를 넘기는 것이 이 스킬의 마지막 동작이다.** 메인 세션은 별도 역할인 지휘자로서 파이프라인을 따른다. 이 스킬은 에이전트를 생성하거나 작업을 배정하지 않는다.

이후의 모든 판단 — 누구를 몇 명 띄울지, 언제 사용자에게 물을지, 언제 되돌릴지 — 은 파이프라인 파일에 있다. 이 문서로 돌아오지 않는다.
