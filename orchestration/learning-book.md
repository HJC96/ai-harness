# 목차에서 학습서까지

메인 세션이 따르는 오케스트레이션 규약이다. 스킬에는 이 팀 구성·순서·단계 승인 규칙을 옮기지 않는다.

## 팀과 절차 연결

| 담당 | 역할 원본 | 사용하는 절차 |
| --- | --- | --- |
| 학습 설계 | [book_planner](../codex/agents/book_planner.toml) | [book-plan](../shared/skills/book-plan/SKILL.md) |
| 자료 조사 | [book_researcher](../codex/agents/book_researcher.toml) | [book-research](../shared/skills/book-research/SKILL.md) |
| 장 집필 | [book_writer](../codex/agents/book_writer.toml) | [book-write](../shared/skills/book-write/SKILL.md) |
| 독립 검토 | [book_reviewer](../codex/agents/book_reviewer.toml) | [book-review](../shared/skills/book-review/SKILL.md) |
| 통합 편집 | [book_editor](../codex/agents/book_editor.toml) | [book-edit](../shared/skills/book-edit/SKILL.md) |

같은 역할의 작업자를 여러 장에 배정할 수 있다. 같은 작업자가 집필자와 검토자를 겸하지 않는다. 설계·조사·집필·검토·편집 사이에서도 역할을 바꿔 재사용하지 않는다.

## 시작과 기록

1. 사용자 요청과 목차를 `books/<slug>/request.md`에 원문으로 보존한다. 사용자 지정 경로가 있으면 그것을 쓴다. 기존 책과 충돌하면 새 경로를 정하고 알려준다. 수정 요청이면 해당 책을 재개한다.
2. 목차가 없으면 목차를 요청한다. 언어·독자·분량만 비어 있으면 한국어, 해당 주제 입문자, 학습 목표를 설명하기에 충분한 분량을 기본값으로 기록하고 진행한다. 주제가 여러 의미로 해석되거나 필수 버전이 불명확할 때만 질문한다.
3. [상태 양식](../templates/book/state.md)을 바탕으로 `state.md`를 만든다. 책 집필 요청의 범위 안에서 작업자를 사용한다. 목차의 삭제·재배열·범위 확장은 사용자 결정이 필요하므로 관련 작업만 대기시킨다.
4. 세션에 커스텀 역할과 서브에이전트 도구가 있는지 확인한다. 역할이 아직 로드되지 않았으면 `codex/AGENTS.md`의 역할 전달 방법을 쓴다. 도구 자체가 없으면 원인을 알리고 `blocked`로 기록한다.

## 의존성과 단계 전환

```text
사용자 입력
  → 학습 설계 → 설계 독립 검토
  → 장별 조사 → 장별 집필 → 장별 독립 검토(사실 축 · 독자 축 동시)
  → 전체 장 통과 → 통합 편집 → 최종 독립 검토 → 전달
```

| 단계 | 배정과 입력 | 통과 조건 | 실패한 경우 |
| --- | --- | --- | --- |
| PLAN | planner에 request, reviewer에 `plan` 범위와 완성된 plan·request | 목차 대응·장 목표·선수 관계가 있는 plan에 최신 `PASS` | planner에 구체적 설계 결함 반환 |
| RESEARCH | researcher에 승인된 plan의 해당 장 | 장별 주장·출처·미확인 사항이 기록되고 필수 근거 공백 없음 | 접근 가능한 자료로 재조사 또는 필요한 사용자 입력 요청 |
| WRITE | writer에 승인된 plan, 해당 research, plan에 적힌 이어받을 문장. 선행 장 전문은 그것 없이 쓸 수 없을 때만 | 배정된 목차 항목을 설명·예제·연습·해설로 풀어쓴 원고와 인수인계 | 설계 문제는 planner, 근거 문제는 researcher, 표현·구성 문제는 writer |
| REVIEW | 독립 reviewer 두 명에게 같은 장을 `chapter-fact`와 `chapter-reader` 범위로 각각 배정하고 request·plan·research를 준다. 독자 축에는 선수 장 원고도 전달한다 | 두 축 모두 현재 대상·입력 해시에 대한 `PASS`, 어느 축에도 미해결 `major` 없음 | 결함 종류에 맞는 담당자에게 재작업 후 두 축 모두 재검토 |
| EDIT | editor에 모든 장, 장별 최신 `PASS`, plan | `book.md`, 읽기 안내, 통합 점검 인수인계 | 누락된 본문은 writer, 설계 충돌은 planner로 반환 |
| FINAL_REVIEW | 독립 reviewer 한 명에게 `final` 범위와 request·book·README·plan·research·원본 장·양쪽 검토 기록 | 최종 대상·입력 해시에 대한 `PASS`, 모든 목차 항목 포함, 링크·해설·사실 보존·학습 가능성 검증 완료 | 편집 결함은 editor, 내용 결함은 원 담당자 수정 후 재조립·재검토 |
| COMPLETE | 리더가 인수인계와 최신 판정 확인 | 실제 최종 파일과 판정 해시 일치, 작업 종료 확인 | 근거가 오래됐거나 미완료면 해당 단계로 복귀 |

`RESEARCH → WRITE → REVIEW`는 **장마다** 진행한다. 책 전체의 상태에는 각 장의 상태를 별도로 적는다. 일부 장만 끝난 상태를 전체 완료로 표시하지 않는다.

## 배정과 동시 작업

- [작업 계약](../shared/instructions/book-contract.md)의 배정 메시지를 사용한다. 경로는 절대 경로로 전달한다.
- 동시 작업자는 기본 최대 3명이다. 런타임의 한도가 더 작으면 그것을 따른다. 역할은 다섯 개지만 동시에 다섯 명을 실행할 필요는 없다.
- plan 검토가 끝나면 서로 독립적인 장의 조사를 병렬화할 수 있다. 동시 배정 여부는 plan의 레벨 표로 판단한다. 같은 레벨의 장은 선행 관계가 없으므로 함께 배정할 수 있고, 표가 없으면 순차로만 진행한다.
- 장 집필은 해당 조사와 plan에 명시한 선행 장의 검토 통과 후 시작한다. 서로의 초안에 의존하지 않는 장만 병렬 집필한다.
- 장 원고 검토는 사실 축과 독자 축을 서로 다른 작업자에게 배정한다. 여유 슬롯이 있으면 동시에 실행하고, 한 자리만 남았으면 순차 실행한다. 두 검토자에게 서로의 검토 문서를 주지 않으며 재검토에는 자기 축의 이전 기록을 준다.
- 한쪽만 발견한 근거 있는 결함도 처리한다. 어느 축이든 `REVISE` 또는 `BLOCKED`이면 다음 단계로 넘기지 않는다. 다른 축의 `PASS`로 상쇄하지 않고, 두 축 모두 현재 판본에 `PASS`일 때만 통과시킨다.
- `plan`·`final`은 장별 축 분리와 다른 검토 범위다. 최종 검토자는 저자·편집자와 독립된 작업자로 배정하고 양쪽 검토 기록의 열람과 통합 판정을 허용한다. 이전 판정을 그대로 복사해 승인하지 않는다.
- 리뷰어는 집필이 멈춘 버전을 검토한다. 리뷰 중인 파일을 수정하지 않는다. 검토 중인 장에 집필자를 함께 배정하지 않는다.
- editor는 장 파일에 쓰지 않는다. 통합 편집은 한 명에게만 배정한다.
- `request.md`와 `state.md`는 리더만 수정하고, 작업자는 고유한 인수인계·검토 파일에 결과를 남긴다.
- 여유 슬롯이 부족하면 완료 작업자의 결과를 저장하고 런타임이 제공하는 종료 방법으로 슬롯을 정리한다. 파일 기록이 있으므로 이후 같은 역할을 새 작업자로 재개할 수 있다.

## 재작업과 중단

- 실패 지적 ID와 수정할 파일을 지정해 원 담당 역할로 돌려보낸다. 같은 미해결 지적에 대해 최대 2회의 수정·재검토까지 진행한다. 작업 ID·작업자가 바뀌어도 횟수를 초기화하지 않는다. 같은 필수 결함이 남으면 `blocked`로 기록하고 해결에 필요한 선택·자료를 사용자에게 알린다. 무한 재시도하거나 기준을 낮춰 완료하지 않는다.
- 근거를 추가할 수 없는 핵심 사실은 추측으로 메우지 않는다. 사용자 자료 제공이나 해당 범위의 변경이 필요하면 질문한다. 그 결함과 무관한 작업은 계속할 수 있다.
- request, plan, research, 선행 장 등 작업의 모든 파일 입력을 경로·SHA-256으로 기록한다. 작업자는 실제 사용한 입력 해시를 인수인계하고 리뷰어는 검토에 사용한 입력 해시도 남긴다.
- 입력 파일이 바뀌면 그 파일을 사용한 작업부터 **의존성 그래프의 모든 후행 작업**을 `stale`로 표시한다. request 변경은 설계부터, plan 변경은 조사부터, research 변경은 해당 장 집필부터, 선행 장 변경은 그 장에 의존한 모든 후행 장까지 전파한다. 공통 입력의 영향 범위가 불분명하면 전체 관련 작업을 무효화한다.
- 본문이 바뀌면 그 장의 판정과 의존하는 후행 원고·판정, 통합본·최종 판정을 무효화한다. 뒤 장의 파일 바이트가 같아도 사용한 입력이 바뀌었으면 이전 `PASS`를 재사용하지 않는다. 각 담당자가 새 입력을 대조해 산출물을 갱신하거나 변경 불필요 근거와 새 입력 해시를 반환한 뒤 다시 검토받는다.
- 통합 편집과 완료 전에는 모든 산출물의 입력 해시가 현재 파일과 일치하고 선행 작업에 `stale`이 없는지 확인한다.
- 최종 편집 중 사실·예제·해설을 고쳐야 하면 editor에게 원고 변경을 맡기지 않는다. 원 담당자가 수정하고 독립 검토를 통과한 뒤 다시 편집한다.

## 재개와 완료

- 재개할 때 request, state, 최신 인수인계와 검토 대상 해시를 확인한다. 사라진 작업자는 자동으로 완료 처리하지 않는다. 실제 산출물을 확인하고 미완료 작업만 재배정한다.
- 중단 후에는 마지막으로 검토된 파일과 현재 파일이 같은지 확인한다. 다르면 해당 검토부터 다시 진행한다.
- 완료 보고에는 `book.md`, 장 파일 디렉터리, 검증 결과, 남은 경미한 한계를 제공한다. 완료가 아니면 부분 산출물과 다음 미완료 작업을 구체적으로 말한다.
- 사용자가 커밋·푸시·게시를 요청한 경우에만 그 후속 작업을 수행한다.
