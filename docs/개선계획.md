# 하네스 개선 계획

참고 저장소(revfactory/harness-engineering-with-cc) 분석과 6개 관점 교차 검토로 정한 계획이다. 방향은 "책 패턴을 통째로 옮기기"가 아니라 **빈 곳만 채우기**다.

## 사용자가 「진행해」라고만 입력했을 때

1. 아래 **진행표**에서 첫 번째 `[ ]` 항목 **하나만** 한다. 다음 항목으로 넘어가지 않는다.
2. 유지보수 작업이다. 책 집필 파이프라인을 시작하지 않는다. 전역 `CLAUDE.md`나 권한 설정은 고치지 않는다.
3. 규격이 바뀌는 항목은 계약(`산출물-계약.md`)을 먼저 고치고 스킬·에이전트를 나중에 고친다.
4. 항목에 "에이전트 없음"이라고 적혀 있으면 서브에이전트를 띄우지 않는다. 띄울 때도 동시에 3개를 넘기지 않고, 결과는 파일로 남기게 하며 리포트 본문을 대화에 옮기지 않는다.
5. 웹 조사는 항목에 적혀 있을 때만 한다.
6. 끝나는 조건을 확인한다. 기본은 `python3 -m unittest discover -s tests` 통과와 `bash scripts/install-claude.sh --doctor` 통과다.
7. 진행표의 해당 항목을 `[x]`로 바꾸고 아래 **진행 기록**에 날짜와 두세 줄 요약을 남긴다.
8. 커밋하지 않는다. 사용자에게는 변경 요약(파일별 한 줄), 실패한 것, 다음 항목의 이름과 권장 effort를 보여 주고 "`/clear` 후 진행해"라고 안내한 뒤 멈춘다.
9. 결정 사항(아래)과 충돌하거나 계획대로 하면 깨지는 것을 발견하면, 고치지 말고 멈춰서 사용자에게 묻는다.

## 결정 사항 (권장안으로 채택, 바꾸려면 이 줄을 고친다)

1. Claude/Codex 구현은 따로 간다. 하나의 계약으로 묶지 않는다.
2. 모델은 기준선 측정(2단계) 전까지 `inherit`를 유지한다.
3. 훅 강도: 기록 + 검수 독립성을 깨는 쓰기만 차단한다.
4. `book.py` 실행 권한 프롬프트는 역할별 훅으로 허용한다. 전역 권한 설정은 건드리지 않는다.
5. 평가 예산: 챕터 단위 픽스처부터. with/without 전체 비교는 하지 않는다(필요하면 사용자가 따로 지시).
6. 기조: 빈 곳만 채운다. 이미 책보다 나은 것(판본 해시, 실제로 도는 게이트, "내 축이 아닌 것")은 유지한다.

## 하지 않을 것

팀 모드(에이전트 간 직접 통신), 강제 PASS, "불확실하면 REDO", 에이전트 파일 7~8섹션 복제, diff만 보는 재검수, `_workspace/` 관례, 새 `manual-queue` 파일, 새 자료조사 역할, 지금 당장의 `references/` 분할.

- [x] **10. 실제 한 바퀴에서 나온 결함** (medium, 에이전트 없음) — 9의 한 바퀴에서 규칙만으로는 해결되지 않은 것. 계약 → 파이프라인·스킬 → `book.py`·`hook.py`·테스트 순
  - 계약에 귀속된 S2·S3에 되돌림 경로가 없다. 설계 검수의 S2는 design 게이트를 막지 않고, 집필자에게도 설계 리포트가 넘어가지 않는다. 그래서 정확성 설계 S2-4(초기 상태가 설계서와 계약에서 다르다)가 고쳐지지 않은 채 집필에 들어갔다. 챕터 검수의 `계약` 귀속 S2·S3(01-정확성 S2-3, 02-정확성 S3-1·S3-2)도 설계자에게 갈 길이 없다. 언제 설계자에게 묶어 보낼지(예: 집필 전 한 번, 또는 계약버전을 올릴 때 동봉)를 파이프라인에 정한다.
  - `<!-- 확인 필요 -->` 주석을 누가 언제 지우는지 정한 규칙이 없다. final 게이트만 주석을 막는다. S2만으로는 재집필이 일어나지 않아서, 이번에는 지휘자가 즉석에서 편집자에게 맡겼다. 그러자 계약 귀속 지적과 같은 줄에 있는 주석 2개가 남아 final이 막혔다. 담당(집필자인지 편집자인지), 근거(정확성 리포트 「근거 확인」 절), 계약 귀속 줄일 때의 경로를 정한다.
  - Bash로 쓴 파일은 기록에 남지 않고 종료 점검에도 들어가지 않는다. 편집자가 챕터 2개를 Bash로 고쳤는데 `.교재기록.jsonl`에는 `index.md`만 남았고, 종료 점검은 「오류 0」을 냈다. 고칠 후보는 두 가지다. 종료 점검이 배정된 쓰기 대상 전체를 보게 하거나, 작업 공간 안에서 Bash로 쓰려 하면 경고를 남기게 한다.
